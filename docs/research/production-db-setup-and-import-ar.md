# تشغيل قاعدة بيانات Masar Startup وأمانها

آخر تحديث: 17 أكتوبر 2026

## الحالة الحالية المؤكدة

- قاعدة Supabase الحية للمشروع هي `axehvaymtcylzjvahism`، والـAPI والواجهة يعملان على Render.
- تم استيراد ستة مرشحين لفرص التمويل الرسمية. جميعها `review`، ولا توجد فرصة منشورة/معتمدة تلقائيًا.
- التحقق الحي عبر GitHub Actions أكد `database: connected`، و`mode: database`، مع صفر فرص مرئية للعامة، وهذا متوقع لأن كل المرشحين قيد المراجعة.
- تم تفعيل RLS على الجداول العامة الأربعة عشر، واستبدال الصلاحيات الافتراضية بمنح صريحة، وإضافة سياسات ملكية مرتبطة بهوية Supabase Auth.
- **واجهة التسجيل وتسجيل الدخول لم تُنفّذ بعد.** السياسات تحمي البيانات عند استخدام Supabase Auth، لكنها لا تعني أن الحسابات أو ملفات المؤسسين أصبحت تدفقًا مكتملًا من الواجهة.

لا ترسل كلمة مرور قاعدة البيانات أو قيمة الاتصال السرية في المحادثة أو في Git. تُحفظ بيانات الاتصال الخاصة في مدير الأسرار لدى مزود الاستضافة؛ مفتاح Supabase المخصص للنشر العام فقط هو المسموح باستخدامه في العميل العام.

## 1. محتوى الفرص الحالية

الاستيراد يحتوي على:
- 6 فرص قيد المراجعة.
- 16 سجل مصدر رسمي.
- 26 معيار أهلية.
- 6 أحداث تدقيق وسجل اكتشاف واحد.

استخدم الاستعلام التالي للقراءة فقط في SQL Editor عند مراجعة فرص التمويل:

```sql
SELECT
  o.slug, o.name, o.organization, o.status, o.support_type,
  o.amount_min, o.amount_max, o.currency, o.deadline,
  o.official_url, o.submission_url, o.official_criteria,
  o.last_verified_at, o.approved_at,
  (SELECT count(*) FROM public.opportunity_sources s
   WHERE s.opportunity_id = o.id AND s.is_official) AS official_sources,
  (SELECT count(*) FROM public.eligibility_criteria c
   WHERE c.opportunity_id = o.id) AS eligibility_criteria
FROM public.opportunities o
WHERE o.slug IN (
 'rise-palestine-startup-grant-review-2026',
 'scale-market-access-matching-grants-review-2026',
 'start-now-interest-free-financing-review-2026',
 'rise-team-company-stipend-review-2026',
 'rise-team-freelancer-stipend-review-2026',
 'safe-palestine-bridge-financing-review-2026'
)
ORDER BY o.name;
```

لا تغيّر `status` إلى `published` ولا تملأ `approved_at` قبل مراجعة الصفحة الرسمية الحالية، والشروط الجغرافية، والمبالغ، وشروط النشاط/التمويل، ورابط التقديم. أُبقي المبلغ فارغًا عندما تتعارض المصادر الرسمية. برنامج Start Now تمويل قابل للسداد دون فائدة، وليس منحة.

## 2. ملخص حماية الصفوف (RLS)

- يربط `users.auth_user_id` سجل Masar الداخلي بهوية Supabase Auth.
- محفّز التسجيل ينشئ الحساب الداخلي بدور `founder` فقط. تعارض البريد الإلكتروني يتخطى الإنشاء بدل ربط المستخدم تلقائيًا بحساب مراجعة/إدارة موجود.
- توابع RLS المساعدة موجودة في مخطط `private`، وليست ضمن مخطط `public` المعروض افتراضيًا عبر Data API.
- يستطيع المستخدم قراءة ملفه وسجلات شركته وطلباته فقط. يستطيع تعديل ملفات شركته وحقول التطبيق المخصصة للمالك، وتحديث حالة قراءة إشعاراته فقط.
- لا يستطيع العميل إنشاء أو تعديل فرص التمويل، أو تغيير دور الحساب، أو الكتابة في نتائج التحليل وادعاءات الأدلة والتدقيق.
- يستطيع العميل العام قراءة الفرص المنشورة والمعتمدة فقط، وكذلك المصادر ومعايير الأهلية المرتبطة بها.
- سجلات الاكتشاف والتدقيق متاحة للمراجعين/المسؤولين بحسب السياسة؛ ومقاطع المصدر متاحة للمراجعين/المسؤولين فقط.

لا تمنح أبدًا دور `reviewer` أو `admin` عبر `raw_user_meta_data` أو نموذج التسجيل. يجب ترقية الحساب من إجراء إداري موثوق. لا تستخدم مفتاح `service_role` في الواجهة الأمامية؛ المفتاح المخصص للنشر العام وحده هو المستخدم لقراءة الفرص العامة من الخادم.

## 3. الاختبارات

التغييرات الأخيرة تختبر:
- بناء TypeScript للـAPI وVite للواجهة.
- استيراد ست فرص ومعاييرها ومصادرها، وعدم نشرها تلقائيًا.
- منع تكرار البيانات والحفاظ على سجلات موجودة.
- اختبار RLS في PostgreSQL مؤقت بهويتين: عدم رؤية ملفات/طلبات المستخدم الآخر، منع رفع صلاحية المؤسس إلى مدير، ومنع إنشاء طلب تقديم باسم مؤسس آخر.
- فحص API الحي على Render: اتصال Supabase، ووضع قاعدة البيانات، وبنية استجابة الفرص.

ملف الاختبار الذي يُجري اختبارات الملكية داخل معاملة ثم يتراجع عنها هو `tests/rls-ownership.integration.sql`. شغّله فقط على قاعدة تكامل مؤقتة، وليس على الإنتاج.

## 4. النشر والنسخ الاحتياطي

متغيرات الربط محفوظة في Environment لدى Render، لا في ملفات المشروع. الخدمة تستخدم:
- `SUPABASE_URL` و`SUPABASE_PUBLISHABLE_KEY` داخل API.
- `VITE_API_BASE_URL` لبناء الواجهة.

Supabase Free لا يتضمن الاحتفاظ اليومي بالنسخ الاحتياطية المُدارة. صدّر نسخة احتياطية خاصة بصورة دورية، وتحقق من إمكانية استرجاعها، وراقب حدود الإيقاف والمساحة في الخطة المجانية. لا تضع النسخة الاحتياطية في Git أو ملفات CI العامة.

## 5. تنبيهات لم تُحسم

- نصوص RISE تتضمن شرط التزام بقيمة 500,000 دولار قبل بدء الاستقبال؛ رقم 510,000 في عدّاد الصفحة لا يثبت وحده أن المال صُرف أو أن الاستقبال ما زال مفتوحًا.
- هناك تعارض في طريقة عرض فترة مبلغ TEAM Company Stipend بين الصفحتين الإنجليزية والعربية؛ لذلك بقيت مبالغها فارغة.
- تختلف جغرافيا TEAM Freelancer بين النظرة العامة والمعايير التفصيلية.
- يعرض SAFE Palestine مسارين للتقديم مع بعض الغموض في حدود الأهلية المالية/التجارية.
- تسجيلات Scale تتبع التمويل المتاح.

كما أشار مستشار أمان Supabase إلى أن امتداد `vector` موجود في `public`. لا يُعدّ ذلك وحده دليل اختراق، لكن يجدر مراجعة نقله إلى مخطط امتدادات مناسب؛ يجب تعديل `db/schema.sql` وطريقة استدعاء نوع `vector` بالتزامن إن تقرر ذلك.
